# 基于STM32的隐私保护无人配送原型系统

## 项目简介
当前外卖配送流程中，用户必须填写精确到门牌号的地址，骑手在配送全程都能看到这些信息。对于独居女性、隐私敏感人群来说，这构成了实实在在的安全隐患。本项目的终极目标，是实现 "信息与实体隔离" 的隐私配送方案

## 开发工具
硬件清单：STM32F103C8T6、ESP8266、L298N、18650电池等。
开发环境：Keil MDK、C语言。

## 文件功能说明

| 文件       | 功能 | 核心内容 |
| --- | --- | --- |
| `main.c` | 主逻辑 | 初始化、指令解析、模式切换 |
| `Motor.c/h` | 电机驱动 | GPIO控制、正反转、差速转弯 |
| `WIFI.c/h` | WiFi通信 | AT指令封装、串口中断接收、缓冲区管理 |
| `OLED.c/h` | 显示驱动 | I2C通信、字符串显示 |

| `Delay.c/h` | 延时函数 | 毫秒级延时 |

## 核心功能实现

1. **通信设计**：基于ESP8266搭建TCP服务器，通过UART中断+环形缓冲区接收数据，设计 `+IPD` 前缀解析算法解决串口数据时序问题。
2. **寻迹算法**：实现4路灰度传感器直线巡线及路口检测。
3. **状态显示**：集成OLED实时显示WiFi连接状态及配送进度。

## 调试日志

### 1. 电机不转：L298N与STM32未共地
- **现象**：代码正确、供电正常，L298N电源灯亮，但电机纹丝不动。
- **排查**：万用表测量STM32的PA0输出高电平3.3V，L298N的IN1端子却只有0.1V。
- **根因**：GPIO输出高电平是相对于自身GND的，两者GND未连通，信号回路是断的。
- **解决**：用杜邦线将L298N逻辑端GND与STM32的GND连接。
- **收获**：共地是嵌入式硬件调试的第一原则。

### 2. ESP8266连接WiFi失败：错误码 `+CWJAP:3`
- **现象**：`AT+CWJAP`返回 `+CWJAP:3` 和 `FAIL`。
- **根因**：目标WiFi名称含 `-5G` 后缀，ESP8266-01S只支持2.4GHz频段。
- **解决**：使用手机开启2.4GHz热点。
- **收获**：IoT开发中，模块频段支持是选型必查项。

### 3. 程序卡死：`printf`无法输出
- **现象**：基础LED闪烁工程正常，加入 `printf` 后程序完全无反应。
- **根因**：Keil默认使用半主机模式，`printf`通过调试器输出，独立运行时无限等待调试器响应。
- **解决**：在 `Options for Target -> Target` 中勾选 `Use MicroLIB`。
- **收获**：从裸机过渡到标准C库时，半主机模式是必踩的坑。

### 4. 串口数据时序匹配问题
- **现象**：手机发 `GO` 电机转，发 `STOP` 不停；或完全无响应，但SSCOM显示数据已到达。
- **排查过程**：
  1. 怀疑 `strstr` 匹配失败，用暴力调试法在OLED打印原始数据，确认数据正确。
  2. 怀疑缓冲区清空时机，调整 `memset` 位置，问题依旧。
  3. 最终发现，主循环检测到 `USART1_RX_CNT > 0` 后立即执行 `strstr`，但串口数据是逐字节到达的，此时缓冲区里可能只有 `0,CON`，还没收完完整的 `0,CONNECT`。
- **根因**：主循环执行速度远快于115200波特率下的串口数据到达速度。
- **解决**：在判断 `strstr` 之前加入 `Delay_ms(100)`，等待一包数据完全到达。
- **收获**：数据到达是异步的，处理器是同步的，必须考虑两者的速度差。

### 5. 上电瞬间电机乱转
- **现象**：一上电电机就转，不是收到 `GO` 才转。
- **根因**：L298N的IN1~IN4引脚内部有上拉。STM32上电后到执行 `Motor_Init()` 之前，PA0~PA3处于浮空输入，被L298N内部上拉拉成高电平，导致误触发。
- **解决**：
  - 软件：`Motor_Init()` 里配置完GPIO后立即使用 `GPIO_ResetBits` 拉低所有IN引脚。
  - 硬件：IN1~IN4各接10kΩ下拉电阻到GND。
  - 操作：调整上电顺序，先启动STM32，再启动L298N。
- **收获**：MCU初始化完成前，外设可能处于不可控状态。

### 6. OLED上电不显示：插ST-Link才正常
- **现象**：Keil烧录后OLED能显示，拔掉ST-Link独立上电不显示。
- **根因**：上电瞬间电机误触发导致电源电压跌落，OLED的I2C初始化失败。
- **解决**：在 `Motor_Init()` 和 `OLED_Init()` 之间加入 `Delay_ms(2000)`，等电源稳定后再初始化OLED。
- **收获**：先锁电机，再等待电源稳定，最后初始化屏幕。

### 7. L298N的5V引脚不是输出
- **现象**：同时接12V和5V时L298N电源灯不亮，模块发热。
- **根因**：5V引脚是逻辑电源输入，不是输出；拔掉跳线帽时，内部7805虽能产生5V，但驱动能力仅几十mA，无法带动STM32。
- **解决**：STM32独立供电，L298N只接12V和GND。
- **收获**：模块引脚的输入/输出属性必须查数据手册，不能凭直觉。

### 8. 面包板内部电气隔离问题
- **现象**：开发板3.3V通过跳线接面包板正极轨，但LED不亮。
- **根因**：面包板左右两侧插排是电气隔离的，开发板横跨中间凹槽，一侧的3.3V无法传导到另一侧。
- **解决**：将跳线移到紧挨开发板3.3V引脚同一排的孔位，或直接从引脚飞线。
- **收获**：面包板内部走线需要实测，不能想当然。

### 9. 中断服务函数为什么不需要在主函数里调用
- **疑问**：`USART1_IRQHandler` 没有在 `main` 里被调用，数据如何写入缓冲区？
- **解答**：中断服务函数由硬件自动调用。USART1收到数据后，硬件置位接收中断标志，NVIC检测到后自动跳转到 `USART1_IRQHandler` 的入口地址执行。函数名在启动文件的向量表中预先定义。
- **收获**：理解硬件、中断向量表、NVIC和中断服务函数之间的协作关系。

### 调试心得
| 问题类型 | 核心教训 |
| --- | --- |
| 共地 | 所有信号交互模块的GND必须连通 |
| 通信协议 | 注意频段、模式、前缀和时序 |
| 上电时序 | MCU初始化完成前，外设可能不可控 |
| 工具使用 | LED指示法、万用表、SSCOM是三大法宝 |
| 代码习惯 | 注意 `while` 分号、半主机模式和缓冲区清空时机 |

## 可能的落地场景

1. **高端封闭社区**：物业采购系统作为增值服务，业主自愿开通；物业费中收取少量隐私配送服务费；楼宇智能化基础好，电梯可联动。
2. **科技园区/写字楼**：园区统一管理，配送需求集中；可与园区门禁系统打通，实现“无接触配送”。
3. **酒店/公寓**：已有送餐机器人基础，可升级为隐私配送模式；与酒店 PMS 系统对接，自动分配房间号。
